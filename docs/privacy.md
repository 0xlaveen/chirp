# Privacy & security

What Chirp keeps, what it sends and where. Each component README has its own, more detailed privacy section: [server](../server/README.md#privacy-and-debugging), [Mac](../mac/README.md) (Live Notes → Privacy), [Android](../android/README.md#privacy) and [iOS](../ios/README.md#privacy--security). The binding rules are in [architecture.md](architecture.md).

- **Nothing is retained by default.** Audio and transcripts live in memory for the length of an utterance, then they are gone. One disk exception, iOS only: the app↔keyboard mailbox holds AES-GCM-encrypted transient text until consumed or expired, deleted on next access (no purge daemon). Opt-in dictation history (Android and iOS) is encrypted on the device and never sent to the Mac. Logs carry only timings, byte counts and error codes. There is no telemetry.
- **Live Notes stay in memory** until you Save or Copy them. Structuring runs on the same local model as clean-up (and is off by default when clean-up points at another host). No autosave, no window restoration, no notes text in logs. Optional speaker labels run on the Mac only.
- **Debug retention is opt-in, local and loud.** With `--debug-retain`, WAV + transcript files are written under `~/Library/Application Support/Chirp/debug/`, expire after three days, and every client shows a persistent red warning.
- **Tailnet-only exposure.** The server binds to loopback (`127.0.0.1:7821`). Publishing it for a phone uses `tailscale serve` (your private tailnet, TLS from the tailnet certificate), never the public internet: the Mac's **Pair a Phone** refuses to pair while Funnel is on.
- **Bearer pairing.** Clients authenticate with a token generated on the Mac: the shared one at `~/.config/chirp/token` (mode 0600), or a named per-device token from `chirp-server pair --name`, revocable with `chirp-server devices revoke` (the server stores only a SHA-256 digest). The pairing QR/link is shown locally only; treat it as a secret. Audio is rejected before authentication succeeds.
- **Clean-up stays on your Mac** in `managed` mode (a local MLX model, forced offline). If you deliberately point correction at an external OpenAI-compatible endpoint, clients label the feature "sends text to \<host\>". Audio never leaves the Mac; only the final text can, and only then.
- **Phone diagnostics are content-free.** Android keeps per-session timings (numbers, booleans and fixed enum names only) and message-free crash frames; no text, audio, URLs, hosts, tokens or app names.
