# Privacy & security

**Your data stays yours.** Chirp has no cloud, no account and no telemetry: your Mac is the server, and audio and text only ever move between your own devices over your own tailnet. This page lists exactly what is kept, what is sent and where. Each component README has its own, more detailed privacy section: [server](../server/README.md#privacy-and-debugging), [Mac](../mac/README.md) (Live Notes → Privacy), [Android](../android/README.md#privacy) and [iOS](../ios/README.md#privacy--security). The binding rules are in [architecture.md](architecture.md).

- **Dictation audio is transient; Mac dictation history is local, sealed and on by default.** Dictation audio lives in memory for the utterance and is never kept. Mac, Android and iOS notes save continuously to a local library on the device that recorded them, kept forever by default (an earlier mobile opt-out stays off), with no Save step. Kept audio is opt-in and off by default. On the Mac, dictation history is on by default (below); on Android and iOS it remains opt-in with separate retention. iOS keeps an AES-GCM sealed Notes library and AES-GCM encrypted transient app↔keyboard mailbox text (deleted on consumption or expiry at next access). Logs carry only timings, byte counts and error codes. There is no telemetry.
- **Mac dictation history stays on this Mac, encrypted.** Every committed dictation is kept so you can find, copy or insert it again: the inserted text, the raw transcript when clean-up changed it, the app it went to (bundle id and name), the time, its length and the clean-up style. It is never kept for a password field (secure input or a secure text field), a cancelled dictation, or an app on Settings → Dictation → History → **Never keep** (password managers by default). Entries live under `~/Library/Application Support/Chirp/History/`, one file per day, each AES-GCM sealed with a 256-bit key held in this Mac's Keychain (service "Chirp Dictation History", not synchronizable; `ThisDeviceOnly` where the build may use the data-protection keychain, else the login keychain, which iCloud Keychain never syncs). The folder is `0700`, files are `0600`, Spotlight is told never to index it, and nothing is synced, uploaded or logged. A file whose key is gone is deleted, never repaired. Retention is 30 days by default (1, 7, 30 or 90 days, or forever). **Clear…** deletes every file and the key; turning history off asks whether to delete what is kept. The first-run window says history is on and where to turn it off.
- **Learn from my edits (Mac) stays on this Mac too.** While history is on, Chirp watches the field a dictation went into (through the Accessibility access it already has) until focus moves, 60 seconds pass or the next dictation starts, and only reads that field's text, never a password field or an excluded app. A fix made twice (or once with **Teach Chirp…** in History) becomes a learned item: one of your terms and the phrase it was heard as, or an app's style preference with a short before/after example. Items are sealed like the history in `~/Library/Application Support/Chirp/Learned/learned.sealed`, with their own Keychain key ("Chirp Dictation History", account `learned-key-v1`), never synced or logged. Active items go with each dictation's `start` to your own Chirp server (and, like the transcript, to the clean-up host if you configured an external one); they never make clean-up add words. Settings → Dictation → **Learn from my edits** turns it off, and **Show Learned…** lists every item with Approve, Undo, Delete and Reset per app.
- **Live Notes stay on the device that records them.** Mac notes live under `~/Library/Application Support/Chirp/Notes/<uuid>/note.json`, with a lightweight `index.json`; folders are 0700 and files 0600. These files are not encrypted by Chirp. Notes are never indexed by Spotlight, synced or logged. Exporting Markdown makes a separate user-chosen copy and does not remove the library note. Existing Recovery journals migrate once. Retention defaults to Never, independently of dictation history; deletion moves notes to Recently Deleted for 30 days before permanent removal. Optional **Keep audio with notes** (Settings → Notes) defaults off and keeps mono AAC segments locally in each note’s `audio` folder, so a transcript paragraph can be replayed. Settings → Notes shows the total with **Delete…**, and each note shows its own size. Turning it off stops future audio storage; deleting existing kept audio is a separate operation that preserves text. Kept audio is never automatically uploaded; future re-transcription requires an explicit request to the user’s own server. Structuring uses the configured clean-up model (off by default when that model is on another host). Optional speaker labels run on the Mac; optional saved voices remain in this Mac’s Keychain, saved only after consent and removable in Settings.
- **Mac call audio is opt-in and stays on your devices.** With **Include call audio** (Notes toolbar → Sources, or Settings → Notes → Sources; off by default), a Mac Live Notes recording also captures what the Mac plays (every app but Chirp, or one app you pick) through a Core Audio process tap, or ScreenCaptureKit audio when no tap can be made; macOS asks for Screen & System Audio Recording once. Capture runs only while a note records. The call audio is mixed into the same 16 kHz stream that already goes to your own Chirp server; nothing else receives it. It is never logged (logs carry the capture kind and counts only), never written to disk except as the mix under the existing opt-in **Keep audio with notes**, and its speaker labels (You for the microphone, Person N for the call) are computed on the Mac. iPhone and Android cannot record other apps' audio, so there is no equivalent there.
- **Android speaker labels are opt-in and keep no voiceprints.** *Label speakers* (Android Settings → Notes or a note's menu, off by default) adds a random per-note session id to each Notes segment sent to your own Chirp server. The server compares the segment's voices with that note's earlier ones using a pinned WeSpeaker model (27 MB, CC-BY-4.0, downloaded from Hugging Face once, only after the phone asks you, and checked against its SHA-256). The comparison state (per-speaker averages of voice embeddings) lives in the server's memory only: never written to disk, never logged, never returned to the phone, and dropped after 6 idle hours, past 32 notes or on restart. The server returns only who spoke which words. The phone stores those turns and the names you give inside the sealed note; logs carry counts and timings only. There are no saved voices on Android.
- **Android keeps your notes, on the phone only.** The Live Notes library (on by default; an earlier opt-out stays off) keeps every note until you delete it: one file per note plus an index, AES-GCM sealed with an Android Keystore key in credential-encrypted storage (nothing is written before first unlock), excluded from backup and device transfer, never logged, never indexed by app search and never synced or sent to the Mac. There is no Save step. Retention is its own setting ("Delete notes older than": Never by default, 1 year, 90 days or 30 days), apart from dictation history. A deleted note stays in Recently Deleted for 30 days. Turning the library off keeps existing notes; *Delete all notes* removes them and the key. A file that cannot be opened is moved aside, never deleted.
- **iOS keeps a sealed local Notes library.** Notes and their index save continuously under the app's Application Support folder, AES-GCM sealed with the existing device-only `notes-recovery-key` Keychain key and a separate `chirp.notes.library.v1` authentication context. Files are owner-only, excluded from backups and protected with complete iOS file protection; writes may wait for unlock. Legacy recovery records migrate idempotently, marked Recovered, with unreadable records quarantined. Notes never enter Spotlight, logs, or sync. Retention defaults to Never and is independent of dictation history. Deletion moves notes to Recently Deleted for 30 days, with Undo and Restore. An earlier explicit storage opt-out stays off; turning storage off preserves existing notes and stops keeping new changes. Copy, Share and Export Markdown make separate user-chosen copies. The Notes Live Activity can show the note title (up to 60 characters), state and time; it never shows the note body or transcript.
- **Kept audio is opt-in, on all three platforms.** *Keep audio with notes* (Mac, Android and iOS, off by default) keeps each spoken segment of a note as a short AAC clip (mono, about 32 kbps) in the note's own folder, with its start offset, duration and sample rate so a later re-transcribe can rebuild the transcript. Silence between segments is dropped. On Android and iOS clips are sealed with the notes key and decrypted only in memory to play; on the Mac they are `0600` files like the note itself. The total is shown in Settings → Notes, and audio is removable per note or all at once (the text stays). Nothing new leaves the device: audio goes only to your own Chirp server, and only when you explicitly re-transcribe (not built yet).
- **Debug retention is opt-in, local and loud.** With `--debug-retain`, WAV + transcript files are written under `~/Library/Application Support/Chirp/debug/`, expire after three days, and every client shows a persistent red warning.
- **Tailnet-only exposure.** The server binds to loopback (`127.0.0.1:7821`). Publishing it for a phone uses `tailscale serve` (your private tailnet, TLS from the tailnet certificate), never the public internet: the Mac's **Pair a Phone** refuses to pair while Funnel is on.
- **Bearer pairing.** Clients authenticate with a token generated on the Mac: the shared one at `~/.config/chirp/token` (mode 0600), or a named per-device token from `chirp-server pair --name`, revocable with `chirp-server devices revoke` (the server stores only a SHA-256 digest). The pairing QR/link is shown locally only; treat it as a secret. Audio is rejected before authentication succeeds.
- **Clean-up stays on your Mac** in `managed` mode (a local MLX model, forced offline). If you deliberately point correction at an external OpenAI-compatible endpoint, clients label the feature "sends text to \<host\>". Audio never leaves the Mac; only the final text can, and only then.
- **The phone's own recogniser is opt-in and labelled.** Android's *Use this phone's recogniser* setting (off by default) lets the keyboard dictate while the Mac is unreachable using Android's on-device speech service from Google or the phone maker, not Chirp's engine. Android documents that recogniser as on-device, but it is a third-party service under its own terms. An **on phone** chip shows every time it is used. See [Android → When your Mac is unavailable](../android/README.md#when-your-mac-is-unavailable).
- **The Android floating mic keeps text in memory only and never copies on its own.** It reads only the focused field's text and selection, with no new accessibility event types, flags or permissions. Words it can't put in the field wait in its panel and are cleared on Done, ✕, screen off or after 2 minutes. Copy is always your tap, and the clip is marked sensitive (Samsung's clipboard history may still keep it). The bubble's saved position is an edge and a height per screen, never text or app names. "Hide in this app" lasts only until you leave that app.
- **Phone diagnostics are content-free.** Android and iOS keep per-session timings (numbers, booleans and fixed enum names only), and Android message-free crash frames; no text, audio, URLs, hosts, tokens or app names.

- **Keeping your Android keyboard is optional.** The input-mode choice and floating-mic skip are ordinary, non-sensitive preferences. Choosing either mode never grants or revokes system permissions. The Accessibility guide discloses focused-field access before opening Android settings; passwords are excluded, field text stays local and is never logged or saved. The service keeps its four event types and 100 ms timeout without additional window-retrieval flags, key-event filtering or an overlay permission. It hides while Chirp Keyboard is selected. Advanced Protection is queried through a normal permission, not bypassed. Notes and Scratchpad work without Accessibility.

### Quick dictate, Speak buttons, widgets and text sharing (Android)

The Dictate tile and widget deliberately **copy the final automatically** so it can be pasted into any app. These are the only dictation paths that auto-copy. Use raw re-copies the original. Every copy sets Android’s `EXTRA_IS_SENSITIVE`; that hides supported clipboard previews, but Samsung’s clipboard history may still retain it. The floating mic copies only after an explicit Copy tap. [Android clipboard privacy](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste#sensitive-content).

A Speak-button request receives only its single final and an unavailable-confidence marker through `RECOGNIZE_SPEECH`’s Activity result. It does not receive history, other notes or clipboard content, and this mode never auto-copies. The requesting app controls what happens to that result. Speech still goes to the paired Mac even when the caller supplies an offline preference. Dictation history remains opt-in: clipboard sessions use “Quick dictate”; Speak sessions use the requesting app’s label when available.

The launcher widget contains static controls only: no note text, dictated words or periodic refresh. Quick dictate is excluded from Recents, disables its screenshot thumbnail where supported, and cancels microphone/network work when left. Scratchpad hand-off is a one-use, expiring in-process value, never a text Intent extra, preference, log or notification.

Plain-text shares into Notes are saved in the existing sealed, local library or appended as the user’s own edit to the same recording/paused note. Sharing alone makes no speech-server request. The text is sent for processing only if the user later chooses Organize. Oversized and non-text shares are refused. The receiver does not return any library data to the sharing app.

## Linux and Windows desktop Notes

Desktop Notes stores text documents and an index locally under the app's per-user
data directory. Linux uses private 0700 folders and 0600 files; Windows verifies a
protected user + SYSTEM ACL before writing note content. These files are not
encrypted, synced or registered with a desktop search index. Notes stay until you
delete them; Recently Deleted keeps them for 30 days unless explicitly emptied.
Export Markdown writes a separate file to the destination you choose.

The desktop streams microphone audio only to your paired Chirp server. It does
not keep audio on disk. Optional smart notes sends each completed transcript to
the same server's configured cleanup model; Organize sends the notes text there.
The server's existing debug-retention and cleanup endpoint settings still apply.
The app reports debug retention when the server advertises it. Tokens stay in
the system credential store; note text, audio and credentials are never logged.
