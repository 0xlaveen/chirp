Set up Chirp on Linux

Install the Chirp server, run it as a systemd user service, build the desktop app, then hold a key and talk into any app. About 30 minutes, most of it downloads. This is new, early software — read the note below before you start.

Before you start

Chirp on Linux runs the same engine as Intel Macs and Windows: Parakeet TDT v2 through ONNX Runtime, int8 on the CPU by default, with CUDA opt-in. Speech recognition stays on this machine; the server listens on 127.0.0.1:7821 only.

Linux support is early — here's exactly what that means.

The server and the desktop app pass their checks in a real Linux environment (unit tests, a real ONNX server transcribing synthetic speech, X11 and Wayland insertion tests, systemd unit validation) — but on Wayland, global shortcuts depend on your desktop's Global Shortcuts portal, so what you get depends on GNOME, KDE or your compositor. Clean-up and Notes structuring run on the CPU and can be slow without a GPU; dictation works without them. The full details live in the repository's Linux guide.

On X11, Chirp observes a single key (Right Alt by default) without grabbing the keyboard, and inserts text with xdotool. On Wayland, you approve a binding in your desktop's shortcut dialog — Chirp suggests Ctrl+Alt+Space — and insertion uses wtype or the clipboard. Xwayland alone doesn't grant global shortcuts for native Wayland apps.

Install the server

  1. Get the prerequisites

    Python 3.13, uv and Git. Then:

    git clone https://github.com/araa47/chirp.git
cd chirp/server
uv sync --locked --extra onnx
  2. Download the speech model 
    uv run chirp-server model fetch --engine onnx

    A pinned, quantized model. Starting the server never downloads weights.

  3. Try it, then check it 
    uv run chirp-server
uv run chirp-server doctor

    Ctrl+C stops the foreground server. For another port use --port 7899.

Files follow XDG: preferences and the token in ~/.config/chirp/, models and server state in ~/.local/share/chirp/, cache in ~/.cache/chirp/. Token files are private to your user; the foreground server never logs spoken words.

Keep it running

uv run chirp-server service install
systemctl --user status dev.chirp.server.service

This renders a private systemd user unit that starts at login, restarts after a crash, and never rewrites your server.toml. Undo it with uv run chirp-server service uninstall. To keep the server running after you log out, an administrator may need to enable lingering for your account — Chirp doesn't change that policy. On machines without a systemd user manager, run the server in a terminal or under your own supervisor.

Install the desktop app

The desktop app is the same Tauri client Windows uses: a tray icon, a live HUD, typed or pasted text insertion and a local Notes library. Install the build dependencies (Debian/Ubuntu shown; see the desktop README for other distros), then build:

sudo apt install build-essential curl pkg-config libwebkit2gtk-4.1-dev libxdo-dev \
  libssl-dev libayatana-appindicator3-dev librsvg2-dev libasound2-dev xdotool xclip
cd desktop
npm ci
npm run build -- --bundles deb

For development, npm run dev runs it unpackaged. On Wayland, also install wtype for compositors that support the virtual-keyboard protocol, or wl-clipboard and paste the result yourself. A Secret Service implementation (GNOME Keyring or KWallet) stores the server token — unlock it before pairing. Chirp never falls back to saving credentials in a preferences file.

Dictate

  1. Click into any text field

    Focus a text field first; the HUD doesn't take focus.

  2. Hold Right Alt and talk

    On X11. An AltGr layout (German, French and others) gets Right Ctrl instead, so AltGr keeps typing its characters. Change the key or switch to tap-to-toggle in settings. The key stays available to other applications; chords cancel dictation.

  3. Release, and it's inserted

    X11 types through xdotool. Multiline results are pasted with xclip and the focused app's paste shortcut, because XTest typing can lose newlines. If automatic insertion fails, the result stays on the clipboard and the HUD asks you to paste it.

On Wayland, turn the shortcut on once.

In settings, tick Enable a global shortcut through my desktop, save, then choose the binding in your desktop's dialog. Chirp shows the binding your desktop approves; single-key holds are available only when the portal allows them. Declining the permission or having no portal leaves Record in the app fully usable.

Notes

Open Notes from the window or tray. Record turns a long conversation into an editable Markdown document beside the transcript; completed 45-second segments save continuously, search covers titles, bodies and transcripts, deleted notes wait 30 days in Recently Deleted, and Export Markdown writes a separate file. Notes are kept only on this computer, under ~/.local/share/chirp-desktop/notes, with 0700/0600 permissions. Desktop Notes store text, never audio.

Structure new segments is opt-in and needs a clean-up model on the server (below). Without one — or with it off — Notes still keep the plain transcript.

Pair a phone or the desktop

The desktop app pairs locally: run uv run chirp-server pair and paste the printed chirp://pair link into the app's Connection & shortcuts settings. The link is a secret; paste it directly, never into chat or logs.

Phones reach a Linux server exactly like a Mac, over your own tailnet and never the public internet:

tailscale serve --bg --set-path /chirp http://127.0.0.1:7821
uv run chirp-server pair --url https://<your-host>.<tailnet>.ts.net/chirp

Clean-up (optional, slow on CPU)

Clean-up is off by default. Two local options, both with the server's safety checks (a timeout or rejected rewrite always preserves the original text):

  • A managed local model — the pinned Qwen3 4B GGUF through llama.cpp (uv sync --locked --extra onnx --extra cleanup, then uv run chirp-server model fetch --cleanup qwen3-4b-instruct-2507-q4-k-m-gguf). On CPU this is slow: a shared-host container measured about 17–20 seconds per clean-up or structuring pass. Dictation itself never waits on it.
  • A local OpenAI-compatible endpoint such as Ollama or LM Studio — usually the nicer option on CPU. Point [correction] at http://127.0.0.1:11434/v1 (Ollama) or port 1234 (LM Studio). Only final text is sent there, never audio.

The exact server.toml blocks for both are in the repository's Linux guide.

If something's off

  • doctor FAILs: it prints a remediation hint per line; the ONNX check wants --extra onnx and the fetched model.
  • The service didn't start: run uv run chirp-server in the foreground to see the error; on Wayland sessions check systemctl --user is available.
  • The shortcut does nothing on Wayland: re-check the portal binding in settings; single-key holds need compositor permission. Ctrl+Alt+Space is the suggested binding.
  • Text isn't inserted: on X11 check xdotool and xclip are installed; on Wayland install wtype or wl-clipboard.
  • Pairing fails: the Secret Service (Keyring/KWallet) must be unlocked first.

Paths, service details and container validation are documented in the repository's Linux guide and desktop README.
