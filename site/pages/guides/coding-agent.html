Build Chirp with your coding agent

Chirp isn’t packaged yet — apps for macOS, Linux, Windows, Android and iOS are coming soon. Until then it installs from source, which is exactly what coding agents are good at. This is the recommended way to get Chirp today.

Works with: any agent that can run shell commands on your MacBest for: a first source install
Start here while Chirp is self-serve.

Paste one of these prompts into the agent you already use in Terminal and work through it together. New to Chirp? See every platform and what’s available today first.

You stay in charge.

An agent can build and install, but some steps are yours: approving the signing identity, granting Microphone and Accessibility, picking models, and anything on your phone. The prompts tell the agent to stop and ask you there, and never to handle your pairing secret.

Install Chirp on this Mac

Help me install Chirp, a local-first voice dictation app, on this Mac from source.
Repository: https://github.com/araa47/chirp

1. Check this Mac runs macOS 14+. Apple Silicon uses MLX (fastest); Intel uses ONNX Parakeet. Windows and Linux support is in progress.
2. Clone the repository (or update it if I already have it) and read README.md,
   mac/README.md and server/README.md before running anything.
3. Make sure Apple's Command Line Tools and uv are installed. Ask me before
   installing either one.
4. From the repository root run ./scripts/install-mac.sh and explain what it is
   doing as it runs.
5. When the Models on this Mac window opens, tell me to download Parakeet v2
   (MLX on Apple Silicon, ONNX on Intel), or v3 (multilingual, Apple Silicon).
   Clean-up is optional: MLX on Apple Silicon, portable llama.cpp or a local
   OpenAI-compatible endpoint on Intel. Dictation works without it.
   Tell me to click Start Local Server. Wait for me to confirm.
6. Tell me to grant Microphone and Accessibility in the Set Up Chirp window.
   Wait for me.
7. Verify the server with its doctor command from server/README.md and tell me
   the result in plain words. Then ask me to hold the Right Option key in a
   text field and say a sentence.

Rules: ask before installing anything or changing system settings. Never use
sudo without asking. Never print, copy or paste the pairing token or a
pairing QR/link. Never enable Tailscale Funnel or expose the server beyond
127.0.0.1 or my tailnet.

Build the Android keyboard

Help me build Chirp for Android from the Chirp repository on this Mac
(https://github.com/araa47/chirp). Chirp for Mac is already working here.

1. Read android/README.md first, especially Install, Pair and Develop and test.
2. Run android/scripts/setup-toolchain.sh (user-scoped, no sudo), then
   source ~/.local/share/chirp-android/env.sh.
3. If android/keystore/local-debug.keystore doesn't exist, run
   android/scripts/make-keystore.sh. If it already exists, never replace it:
   Android would refuse updates signed with a new key.
4. In android/, run ./gradlew assembleRelease and tell me where the arm64 APK is.
5. Tell me how to install it on my phone (Taildrop or adb install -r) and wait.
   Don't touch my phone yourself unless I say so.
6. Walk me through pairing: Settings → Devices → Pair a Phone… on the Mac,
   then Scan pairing QR on the phone. I will scan it myself.

Rules: never print, log or paste the pairing token, QR or link. Never enable
Tailscale Funnel. Ask before changing any Tailscale setting.

Change Chirp to suit you

It's your copy. Good first changes: a clean-up style for how you write, different per-app styles, or a new sound. Describe what you want where it says so:

I use Chirp (https://github.com/araa47/chirp), checked out on this Mac. I want
to change it: <describe the change, e.g. "a clean-up style for commit messages">.

1. Read README.md, docs/architecture.md and the README of the component you'd
   change (server/, mac/, android/ or ios/), and docs/TESTING.md.
2. Propose the smallest change that does it, matching the surrounding code
   style, and wait for my OK.
3. Make it on a new git branch, add or update tests, and run that component's
   full test command from its README.
4. Keep Chirp's privacy rules: no dictated text, audio, tokens or URLs in logs,
   files or test fixtures.
5. Tell me how to rebuild and reinstall to try it.

Many settings don't need code at all: clean-up prompts, styles, per-app styles, hotkeys and models are all editable in Chirp's Settings.
